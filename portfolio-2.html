Resolving a gateway incident with Bash and OpenShift.

Automating a ConfigMap reference correction across approximately 42 deployments per zone in two OpenShift zones.

Nov 2024 – PresentProfessional experience
  • Bash
  • OpenShift
  • ConfigMaps
  • Incident response

01 / The incident

Gateways were picking up the wrong configuration.

Gateways across multiple services referenced the wrong ConfigMaps and were not using the intended configuration. The references pointed to OCU rather than the required PRO configuration.

02 / My automation

Export. Correct. Reapply.

During the incident, I developed a Bash script that exported the OpenShift deployment manifests, corrected the ConfigMap references from OCU to PRO and reapplied the updated deployments.

The correction covered approximately 42 deployments per zone across bo1 and bo2. The script applied the repeated changes as part of resolving the incident.

03 / The correction

Corrected configuration references across both zones.

I corrected the misassigned ConfigMap references through a Bash script developed during the incident. This combined application troubleshooting with automation of the repeated deployment updates.

04 / The context

Production operations within a banking delivery process.

At UST, my role for Banco Santander centres on production releases and application operations. My role is Developer III – DevOps Engineering.

05 / My contribution

Operating releases and investigating application issues.

I carry out production releases through Shuttle, approve GitHub Actions pipeline runs and execute Jenkins pipelines. I monitor application behaviour, support incident investigation and contribute to occasional GitHub Actions pipeline onboarding.
